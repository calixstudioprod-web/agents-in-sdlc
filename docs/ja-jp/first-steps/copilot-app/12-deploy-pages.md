Space Quiz を GitHub Pages に公開して、誰でもアクセスできるようにします。Copilot はワークフローを準備し、公開を案内できますが、変更内容をレビューし、サイトが公開されたことを確認する責任はユーザーにあります。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages への公開設定を依頼します。
- マージする前に、ワークフローとプルリクエストをレビューします。
- 公開の進行状況を確認し、サイトが公開されたことを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、簡単に試せる方法が必要です。1 ファイルのサイトを GitHub Pages で公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にサイトの公開を依頼する

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要であれば Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。まだ `README` がない場合は、アプリの説明とローカルでの実行方法を記載した `README` を追加してください。これらの変更を含むプルリクエストを作成し、必須チェックに合格したらマージしてください。デプロイが成功するまで監視し、その後、公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、何を承認または実行する必要があるかを正確に教えてください。サイトが公開されるまでは、成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、diff、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローをレビューして公開を確認する

1. リポジトリに `README` がない場合に限り、`README` が追加されていることを確認します。
2. ワークフローのビルド手順とデプロイ手順を含め、プルリクエストの変更内容をレビューします。
3. 必須のプルリクエストチェックに合格した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages を有効にできない場合やプルリクエストをマージできない場合は、提示された具体的な手順に従います。デプロイが成功し、公開サイトが読み込まれるまでは、タスクを完了したとみなさないでください。
